# 部署归属方案：陌生人 IM / 办公内网

状态：已定，按本文实现。不要再讨论「要不要拆仓库」或「运行时切换」。

本文给实现用。先读背景和「不要做什么」，再改代码。

---

## 1. 项目背景

海狸 IM 是 MIT 开源、私有化部署的即时通讯。一套安装跑在部署方自己的机器上。

仓库分工（不要新建仓库）：

| 仓库 | 职责 |
|---|---|
| `beaver-server` | Go + go-zero。用户、鉴权、好友、群、聊天、长连接、文件、朋友圈、圈子、通话、开放平台、网关 |
| `beaver-desktop` | Electron + Vue 3。宿主窗口加能力包，不是多个客户端 |
| `beaver-flutter` | 移动端。本方案不改，但读同一个归属字段 |
| `beaver-agent` | 独立 AI（`agent_api`）和 IM 内置助手（`agent_rpc`）。本方案不改 |
| `beaver-manager` | 运营后台。本方案不改 |

服务端按库拆分，迁移入口是 `database/migrations.go` 的 `AllMigrations()`。现有库包括 `beaver_user`、`beaver_auth`、`beaver_friend`、`beaver_group`、`beaver_chat`、`beaver_moment`、`beaver_circle` 所在服务、`beaver_file`、`beaver_call`、`beaver_open`、`beaver_platform`、`beaver_notification`、`beaver_backend`、`beaver_datasync`。用户表是 `user_models.UserModel`：一个全局 `userId`，手机号或邮箱注册。用户类型只有三种：`1` 普通用户、`2` 通知机器人、`3` 智能机器人。没有组织，没有部门。`OpenDeveloper.CompanyName` 只是开发者登记，不是租户。

桌面端侧边栏在 `beaver-desktop/src/render/windows/app/components/layout/sidebar/data.ts`：

- 核心：聊天、好友
- 扩展：圈子（`app-circle`）、工作台（`app-workbench`）、朋友圈（`app-moment`）、AI

圈子、朋友圈、工作台已经是独立能力包。办公内网是少挂几块、多挂一块通讯录，不是再做一个 Electron。

### 1.1 已经有的 AI，不要在本方案里重做

这些是另一条产品线，本方案只保证它们在两种归属下都还能用聊天和开放平台：

| 能力 | 在哪 | 行为 |
|---|---|---|
| 群推送（通知机器人） | `beaver-server`，`UserType=2`，`OpenBotModel` | 单向 Webhook，收不到回复 |
| 智能机器人 | `beaver-server`，`UserType=3`，`OpenRobot`，`/api/open/ws/v1/connect` | 双向，能被 @ |
| 龙虾（OpenClaw） | 外部程序，走智能机器人长连接 | 不在本仓库 |
| IM 内置助手 | `beaver-agent` 消费 `agent_task` | 服务端投递尚未接上，另案，不要塞进本次 |
| 独立 AI | `agent_api` + 桌面 AI 窗口 | 不进 IM 聊天入口 |

### 1.2 为什么要做归属

陌生人 IM 和办公内网是两种安装结果，不是同一个人用的时候再切换。

- 陌生人：人自己注册。关系是好友、群、圈子、朋友圈。数据归这个人。
- 办公内网：安装时就有且只有一个组织。人由组织拉进部门。没有好友申请，没有朋友圈，没有圈子。人离开组织，账号可以停用，聊天和文件留在这套安装里。

私有化意味着一套进程只服务一种归属。飞书那种「个人和企业来回切」不做。

---

## 2. 决定

1. 一套 `beaver-server`，一套 `beaver-desktop`。不拆仓库，不拆客户端。
2. 归属在第一次初始化写入数据库，之后不可改。改配置文件不算切换。
3. 取值只有 `social`（陌生人）和 `office`（办公内网）。
4. 已有数据、但还没有归属行的安装，一律视为 `social`。禁止把已经有好友或朋友圈的库初始化成 `office`。
5. 部门不是 `UserModel` 上的字段。办公内网单独建组织库。一个安装只有一个组织。
6. 两种归属共用：登录、聊天、长连接、群、文件、表情、通话、通知、开放平台（含两种机器人）、工作台、网关。
7. 服务进程照常注册。不按归属停掉某个微服务。归属不对的接口直接拒绝。

---

## 3. 不要做什么

- 不要运行时开关，不要在设置里提供「切换成办公」。
- 不要支持多个组织，不要 `org_id` 做成租户切换。
- 不要把好友关系迁成部门，不要把圈子改造成部门。
- 不要做在线文档、日历、审批、邮件。聊天里已有的云文档消息类型（`CloudDocMsg`，消息 type 15）保持卡片，后面没有文档服务，本次不动。
- 不要改 `beaver-agent`，不要接 `agent_task`。
- 不要为办公内网新建用户类型。人仍然是 `UserType=1`。
- 不要让客户端自己猜归属。只信服务端返回的 `mode`。

## 4. 数据

新库名：`beaver_org`。在 `database/migrations.go` 的 `AllMigrations()` 增加一项。`social` 也建空库，避免迁移分叉；`social` 下这三张表必须是 0 行。

### 4.1 `org_instance`（全库只允许一行）

| 字段 | 说明 |
|---|---|
| `mode` | `social` 或 `office` |
| `initialized_at` | 写入时间，毫秒 |

没有第二行。更新 `mode` 的代码路径不要写。

### 4.2 `org_organization`（`office` 时恰好一行，`social` 时 0 行）

| 字段 | 说明 |
|---|---|
| `org_id` | 字符串，唯一 |
| `name` | 安装时配置的组织名，缺省「海狸」 |
| `owner_user_id` | 组织拥有者。默认同 `database/user/seed.go` 的 `ownerUserID`（`100000`），该用户须已存在 |

### 4.3 `org_department`

| 字段 | 说明 |
|---|---|
| `dept_id` | 字符串，唯一 |
| `parent_id` | 空字符串表示根。根只有一个，初始化时创建，名为组织名 |
| `name` | 部门名 |
| `sort` | 同级排序 |

删除前：有子部门或有成员则拒绝。根部门不可删。

### 4.4 `org_member`

| 字段 | 说明 |
|---|---|
| `user_id` | 对应 `UserModel.UserID`，唯一（一个人在这一套安装里只属于一个部门） |
| `dept_id` | 所属部门 |
| `role` | `1` 拥有者、`2` 管理员、`3` 成员。拥有者只有 `owner_user_id` 那一行 |

不要把 `dept_id` 加到 `beaver_user`。

## 5. 初始化

在现有迁移和 `userseed.InitDefaultUser`、`openseed.InitQuickLoginApp` 之后执行，只跑一次。

配置只在「还没有 `org_instance` 行」时生效，建议放平台或启动配置：

```yaml
Deploy:
  Mode: social   # social | office
  OrgName: 海狸  # 仅 office 使用
```

规则：

1. 已有 `org_instance`：忽略配置里的 `Mode`。若配置值不同，打错误日志，继续用数据库的值。
2. 没有行，且 `Mode` 不是 `social`/`office`：启动失败。
3. `Mode=social`：插入一行 `social`。不插入组织和部门。
4. `Mode=office`：若 `beaver_friend` 或 `beaver_moment` 已有业务行，启动失败，提示只能作为 `social`。否则插入 `office`、一行组织、一个根部门，并把 `100000` 写入 `org_member`（角色拥有者，部门为根）。`100000` 不存在则先依赖现有用户种子，不要另造一套默认用户。
5. 已有库、没有归属行、也没有这份新配置：按 `social` 写入。这是给当前已经在跑的陌生人安装用的，避免升级后变成办公内网。

## 6. 接口

归属查询所有人可调用（登录前也要能读，桌面端启动就要拿）：

`GET /api/platform/v1/instance`

```json
{
  "mode": "office",
  "org": {
    "orgId": "...",
    "name": "海狸"
  }
}
```

`social` 时 `org` 为 `null`。挂到现有 `platform` 服务，并加入网关 `PublicList`（与 `update_public` 一类公开接口相同的原因：登录页就要知道这套安装是什么）。

办公接口前缀 `/api/org/v1/`。`mode!=office` 时全部返回业务错误，文案固定：`当前安装不是办公内网`。建议码使用项目里已有的业务错误风格，不要发明 HTTP 401。

| 方法 | 路径 | 谁能调 | 行为 |
|---|---|---|---|
| GET | `/api/org/v1/department/tree` | 已登录成员 | 返回部门树，节点带成员人数，不带全量成员 |
| POST | `/api/org/v1/department` | 拥有者、管理员 | `parentId` + `name`。父部门必须存在 |
| PATCH | `/api/org/v1/department` | 拥有者、管理员 | 改名、改父级、改排序。不能把部门挪到自己的子孙下，不能改根的父级 |
| DELETE | `/api/org/v1/department` | 拥有者、管理员 | 见 4.3 |
| GET | `/api/org/v1/member/list` | 已登录成员 | 可按 `deptId` 过滤。返回 `userId`、昵称、头像、`deptId`、`role` |
| POST | `/api/org/v1/member` | 拥有者、管理员 | 把已注册的 `userId` 放进部门。已在组织中则拒绝，本次不提供「调动部门」 |
| DELETE | `/api/org/v1/member` | 拥有者、管理员 | 移出组织。不能移出拥有者 |

本次不做：邀请链接、批量导入、按部门建群、部门群自动同步成员。

`social` 下好友、朋友圈、圈子接口保持现状。`office` 下这些接口拒绝，文案：`当前安装不是陌生人 IM`。至少包住：

- `friend` 的申请、同意、列表
- `moment` 的发布和列表
- `circle` 的创建、加入、列表

实现方式：各 logic 入口查一次归属（进程内缓存，启动时加载，不要每个请求查库）。拒绝发生在业务逻辑，不靠停进程。

群：两种归属都保留。`office` 下建群、拉人不再要求对方是好友。`social` 下维持现在的好友校验。不要改消息表。

登录和注册：两种归属都还用现在的手机号/邮箱账号。`office` 不在本次做「关闭公开注册」。管理员把已经注册的用户加入部门即可。

## 7. 桌面端

仓库：`beaver-desktop`。一个安装包。

启动后、进主界面前请求 `GET /api/platform/v1/instance`，结果放进现有应用 store（与 `sidebar/data.ts` 的导航同源）。请求失败则停在错误页，不要默认当成 `social` 把好友入口放出来。

按 `mode` 决定侧边栏，改 `sidebar/data.ts` 的使用处，不要复制一套窗口：

| 入口 | `social` | `office` |
|---|---|---|
| 聊天 | 显示 | 显示 |
| 好友 | 显示 | 隐藏 |
| 通讯录（部门树） | 隐藏 | 显示，占好友原来的位置 |
| 圈子 | 显示 | 隐藏，且不要 `openWindow('circle')` |
| 朋友圈 | 显示 | 隐藏，且不要 `openWindow('moment')` |
| 工作台 | 显示 | 显示 |
| AI | 显示 | 显示 |
| 通话、设置、表情 | 显示 | 显示 |

通讯录是主窗口里的一页，数据只来自第 6 节的部门树和成员列表。不要新建 `packages/app-*`，除非现有主窗口页面塞不下。朋友圈和圈子的包留在仓库里，只是办公安装不挂。

客户端不提供切换。不把 `mode` 写入用户可编辑的本地配置。可以缓存接口结果，下次启动仍以服务端为准。

`beaver-flutter` 本次不改。

## 8. 验收

陌生人安装（默认，或 `Deploy.Mode=social`）：

- `org_instance.mode=social`，组织表和部门表为空。
- 好友、圈子、朋友圈与现在一致。
- `/api/org/v1/*` 被拒绝。
- 桌面端没有通讯录，好友、圈子、朋友圈还在。
- 重启后把配置改成 `office`，日志报冲突，界面仍然是陌生人。

办公安装（空库，`Deploy.Mode=office`）：

- 恰好一个组织、一个根部门，`100000` 是拥有者。
- 好友申请、朋友圈、圈子接口被拒绝。
- 桌面端是通讯录，没有好友、圈子、朋友圈。
- 管理员能建子部门、把另一个已注册用户加入部门、成员能看到树。
- 不能删除根部门，不能移出拥有者，不能把已在组织中的人再加入一次。
- 两人不是好友也能被拉进同一个群，并能正常收发消息。
- 通知机器人和智能机器人的现有接口还能调用。

升级安装（已有好友数据、没有 `org_instance`）：

- 启动后自动写成 `social`，好友数据还在。
- 不会创建组织。
